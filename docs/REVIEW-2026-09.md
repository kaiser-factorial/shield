# shield — architecture & code review (2026-09-10)

Scope: full read of `src/`, `bin/`, `python/shield/`, tests, packaging, CI, docs, at
v1.4.2 (TS) / v1.4.1 (Python). Every defect marked **[verified]** was reproduced
against the built package in this session; timings are from Node 22 / CPython 3.12.

Goal being reviewed against: *"import it into any app I make so it can track
potentially problematic LLM output **and** general security issues."*

---

## 0. Verdict

The core primitives (detect / wrap / harden / canary / event bus) are small, readable,
well-commented, and the tests are real. The v1.3–1.4 hardening work (tag-breakout
sanitization, CSPRNG salt, streaming canary, event-bus isolation) is sound.

But the library as it stands does **not** meet the stated goal, for three structural
reasons:

1. **It is an input scanner with a single output check.** The only thing it inspects
   in *model output* is the canary token. There is no output-side detection of
   secrets, PII, exfiltration URLs / markdown images, unsafe tool calls, or the model
   echoing untrusted-block instructions. "Track problematic LLM output" is the
   roadmap item the HANDOFF itself calls "the biggest gap".
2. **It is a personal tool, not a package.** Global singletons, a hard-coded
   `~/.shield/events.jsonl` sink, `@local/shield` name, `file:../shield` installs,
   personal app names and home-directory paths baked into README/HANDOFF/launchd, a
   macOS-only `ps`-scraping "general security" feature, and version drift between the
   two halves (1.4.2 vs 1.4.1) that the "parity rule" already failed to catch.
3. **The wrappers are not drop-in, and in Python they fail silently.** Anything off
   the narrow `messages.create/parse/stream` and `chat.completions.create` path is
   either missing (TS: `TypeError` at call time) or **passed through with no
   hardening at all** (Python: `client.chat.completions.parse`, `client.responses`,
   `client.beta.*`). The Python case is exactly the wearabLLM failure mode the whole
   v1.1 design exists to prevent: protection that looks on but isn't.

There are also two **[verified]** bugs that matter for a library that scans
attacker-controlled input and promises durable logging: a ReDoS in the pattern set,
and event loss at process exit / before logger init.

## 1. Confirmed defects, ranked

### P0 — ReDoS in the detection regexes (both languages) **[verified]**

Two patterns are super-linear on whitespace:

| pattern | why | TS 40k chars | Python 40k chars |
|---|---|---|---|
| `untrusted-tag-breakout` `[<＜]\s*\/?\s*untrusted` | two adjacent `\s*` around an optional `/` | 1.5 s | 7 s |
| `system-colon` `^\s*(system\|admin\|operator)\s*:\s+` (multiline) | `^` matches at every line start and `\s*` includes `\n`, so every position rescans to end | 3.8 s | **31 s** |

Benign 40k-char prose scans in 1 ms. A fetched web page or tool result is
attacker-controlled and routinely 100k+ chars, so this is a trivially triggerable
CPU stall on every request path shield protects — and `sanitizeUntrusted` uses the
same breakout regex, so `wrapUntrusted` stalls too.

Fix: `[<＜][ \t]*\/?[ \t]*untrusted` (or `\s{0,4}`) and
`^[ \t]*(system|admin|operator)[ \t]*:[ \t]+` (don't let `\s` cross lines after `^`).
Add a regression test that asserts scan time on `"<" + " "*100_000` and
`"\n"*100_000` stays under ~50 ms. Consider a global input-length cap (scan the
first N KB plus tail) with an `input_truncated` flag on the result.

### P0 — Events are lost at process exit and before `initFileLogger()` **[verified]**

`appendEvent` does `await import("fs")` on first use. If the process exits
synchronously after emitting (the CLI's own `shield headless` one-shot does
`reportHeadless(); process.exit(1)`), **nothing is written** — reproduced: 0 lines
persisted. Any short-lived script, serverless handler, or test runner hits this.

Separately, the README's wrapper examples never call `initFileLogger()`, and the
`shield_started` heartbeat is emitted in the constructor. If an app follows the
README, or calls `initFileLogger()` after constructing the client, the heartbeat is
emitted to zero subscribers and never persisted — reproduced: 0 heartbeats logged.
`shield status` then reports "never announced" for a correctly wired app, which is
the exact false alarm the status feature exists to avoid.

Fix: use a static `import * as fs from "node:fs"` behind a runtime `typeof
process` guard (or split a `/node` entry point — see §2), write synchronously, and
have the bus keep a small ring buffer of pre-init events that a late subscriber
drains. Have the wrappers call `initFileLogger()` themselves when running under
Node unless told not to.

### P0 — Python wrappers silently bypass shielding for any non-wrapped method **[verified]**

`_CompletionsProxy.__getattr__` / `_MessagesProxy.__getattr__` /
`ShieldAnthropicClient.__getattr__` forward everything they don't override
straight to the inner SDK. Verified: `client.chat.completions.parse(...)` receives
no system prompt and no scan; `client.responses`, `client.beta.messages` are
returned unshielded. OpenAI's `responses` API is now the primary API, so a new app
written today is most likely to be entirely unprotected while the banner says
"active".

Fix: deny-by-default. Forward only an explicit allow-list of known-safe
attributes (`models`, `embeddings`, `files`, `_client`, …); for LLM-call surfaces
that aren't shielded, raise `ShieldCoverageError` (or wrap them). Add
`responses.create` and `beta.messages` coverage or make their absence loud.

### P1 — TS wrappers are not drop-in **[verified]**

- OpenAI: `get chat()` spreads `inner.completions`. Spread copies own enumerable
  props only, so prototype methods vanish: `chat.completions.parse`, `.stream`,
  `.runTools` are `undefined`. `responses`, `embeddings`, `models` don't exist on
  the wrapper at all.
- Anthropic: `messages.countTokens`, `messages.batches`, `beta` are `undefined`.
  `parse` is always exposed even when the inner client lacks it.
- The TS `ShieldOpenAIClient` is typed against the concrete `openai` class and its
  emitted `.d.ts` does `import type OpenAI from "openai"`. A consumer with
  `skipLibCheck: false` and no `openai` installed gets a type error from `index.d.ts`
  even if they only use the Anthropic wrapper. The Anthropic wrapper is correctly
  duck-typed; make OpenAI the same.

Fix: use a `Proxy` over the inner client that intercepts a known set of call
paths and throws on unknown LLM-call surfaces (same deny-by-default as Python).

### P1 — Node 18 crash at import

`strongSalt()` runs at module scope and requires `globalThis.crypto`. That global
is unflagged only from Node 19; the comment says "Node ≥18". On Node 18 LTS the
package throws on `import`. Use `node:crypto`'s `randomUUID` via a guarded static
import, and add an `engines` field.

### P1 — Home-directory resolution

`HOME ?? "~"` yields the literal path `~/.shield/events.jsonl` (reproduced) when
`HOME` is unset (systemd units, containers, Windows where it's `USERPROFILE`). Use
`os.homedir()`; better, make the sink path configurable (`SHIELD_LOG_FILE`, or an
option) — a library "for any app" cannot assume a writable home dir.

### P1 — `readEvents` discards the entire log on one bad line

`lines.map(JSON.parse)` inside one `try` → a single truncated line (e.g. from a
crash mid-write, or two processes appending concurrently) makes `shield logs` and
`shield status` report "no events". Parse per line and skip/count failures.

### P2 — `wrapUntrusted` label is not sanitized **[verified]**

`wrapUntrusted("x", "page>title<script")` produces
`<untrusted_page>title<script>` — the label is interpolated into a tag with only
whitespace replaced. Labels usually come from code, but bulwork uses "dynamic
per-call source strings" per the README. Restrict to `[a-z0-9_]`.

### P2 — Zero-width and lookalike evasion of the tag-breakout sanitizer **[verified]**

`</​untrusted_x>` passes `sanitizeUntrusted` unchanged and also isn't
detected. Models routinely ignore zero-width characters. NFKC-normalize and strip
`​-‏⁠﻿` before both scanning and sanitizing (this also fixes
the fullwidth-letter miss in §3).

### P2 — Canary false positives on normalized compare

`outputLeakedCanary` strips non-alphanumerics and lowercases both sides, so the
canary `SHLD-8905CQ` matches the output substring `shld8905cq` anywhere — 6
base-36 chars is ~31 bits, fine, but the Python canary is `SHLD-` + 32-bit hex
(`%06X`), which is 6–8 hex chars and formatted differently from TS. Unify the
format, lengthen to ≥ 10 chars, and document it.

### P2 — Prompt caching across processes / workers

The salt is per-process, so every worker, lambda instance, or restart produces a
different system prompt suffix → cache miss on the whole (often large) system
prompt. `hardenSystemPrompt(base, canary)` accepts a fixed canary but the wrappers
don't expose it. Add `canary` / `canarySalt` options and document `SHIELD_CANARY_SALT`
for horizontally scaled deploys.

### P2 — Anthropic `document` blocks are not scanned or wrapped

`type: "document"` (text/plain or PDF) is a first-class indirect-injection channel
and is skipped by `extractText` / `wrapUserContent`. Scan `source.data` for
text-typed documents; at minimum emit a `not_scanned` event.

### P3 — Assorted

- Cross-language timestamp compare in `summarizeStatus` is lexical; Python emits
  `+00:00` with microseconds, TS emits `Z` with ms, so ordering is wrong across
  languages. Parse to epoch.
- `scanDetail` caps at 300 (TS) vs 200 (Python); Python `excerpts` lack
  `line`/`index` (parity already broken at 1.4.2).
- Python `emit_event` opens + chmods the file on every event; no in-memory bus, no
  way to subscribe or redirect.
- `sanitizeForTerminal` doesn't strip bidi overrides (`U+202E`) — a log line can
  still be visually reordered.
- `tapEventStream`: `extract(r.value)` isn't guarded; a malformed chunk throws into
  the consumer. `Stream.tee()` / `toReadableStream()` bypass the tap.
- React: context value object is rebuilt every render → all `useShield` consumers
  re-render on every provider render. `useMemo` it.
- CLI: `--limit abc` → `NaN` → no limit; `--type` accepts any string silently.
- `package.json` `exports`: `types` should precede `import`; no `require` condition;
  no `browser` condition (index re-exports Node-only modules); no `engines`;
  `sideEffects` unset (module-scope salt + console side effects).
- CI: single Node version, no lint/format, no `npm audit`, no Python type check
  (the codebase is annotated but nothing runs mypy/pyright), no publish workflow.
- `launchd/*.plist` hardcodes `/Users/corinakaiser/...`; `.gitignore` contains a
  stray `shield-py alias` line.

## 2. Architecture: what "importable into any app" needs

Today everything is module-level global state: `logHandlers`, `announcedLabels`,
`CANARY_SALT`, `initialized`, and a fixed file sink. That is fine for one person's
laptop and wrong for a library.

**Target shape (TS; mirror in Python):**

```
@yourscope/shield            core, isomorphic, zero deps
  createShield(config) -> Shield
    .scanInput(text, {source})        InjectionScan
    .scanOutput(text, {source})       OutputScan   (new — §4)
    .wrap(text, label)
    .harden(systemPrompt)
    .checkCanary(output)
    .on(event, handler) / .events
  config: { app, canarySalt?, sinks: Sink[], detectors: Detector[], redact: bool,
            thresholds, maxScanBytes }
  default instance exported for convenience (getDefaultShield())

@yourscope/shield/node       fs sink (JSONL), rotating, path configurable,
                             OTel / webhook sink, process watch, CLI
@yourscope/shield/anthropic  wrapper (duck-typed, Proxy-based, deny-by-default)
@yourscope/shield/openai     wrapper (chat.completions + responses)
@yourscope/shield/react      provider/hooks
```

Key properties:

- **Instance, not globals.** Two apps (or two tenants) in one process get separate
  config, sinks, and canary salts. Tests stop needing to reset module state.
- **Sinks are pluggable.** JSONL file is one sink. Add a console/structured-log
  sink, an HTTP/webhook sink, and an OpenTelemetry sink; an app in a container
  with a read-only home dir must still be able to emit somewhere. Keep the
  in-memory ring buffer so late subscribers and pre-init events aren't lost.
- **Event schema is versioned and richer.** Add `schema: 1`, `app`, `env`,
  `pid`/`host`, optional `requestId`/`sessionId`, `direction: input|output|tool`,
  `channel: user|tool_result|document|system`, `version`. Right now `source` is an
  overloaded string with a `:tool_result` suffix convention.
- **Redaction is a first-class option.** `detail` stores raw user content on disk.
  Offer `redact: "hash" | "excerpt" | "none"`.
- **Node-only code never reaches the isomorphic entry.** `index.ts` currently
  re-exports `headless.ts` and `logger.ts`; bundlers that don't tree-shake pull
  `child_process` references into browser builds.
- **Publish it.** Real npm/PyPI names, `engines`, a changelog, a single version
  source (a script that stamps both `package.json` and `pyproject.toml` and a CI
  check that they match — the manual "parity rule" is already broken).

## 3. Detection quality (measured)

The regex layer is honest about being a tripwire, but at threshold 0.5 it is
noisy in one direction and blind in the other:

**False positives at default threshold [verified]:**

| input | score |
|---|---|
| "Can you act as a translator for this Spanish text?" | 0.50 flagged |
| "what are your rules for refunds?" | 0.60 flagged |
| "Let us roleplay as pirates for the kids party" | 0.50 flagged |
| "System: scheduled maintenance tonight at 10pm" | 0.70 flagged |
| "Pretend you are a customer and rate our checkout flow" | 0.60 flagged |

**Misses [verified]:** zero-width-joined `ig​nore`, fullwidth
`ｉｇｎｏｒｅ`, hyphen-spaced `i-g-n-o-r-e`, base64, and any non-English phrasing
all score 0.00.

Recommendations:

- Normalize before matching: NFKC, strip zero-width/format chars, collapse
  repeated separators between letters, then also scan a de-hyphenated variant.
- Drop `act-as` / `roleplay-as` / `what-is-your-system` to 0.3–0.4 so they only
  flag in combination, and require `system-colon` to be at the very start of the
  text or preceded by a blank line.
- Add high-signal, low-FP patterns that are missing: markdown-image / URL
  exfiltration (`![...](http...?` + long query), "send/post/email this to",
  "encode/translate the above", "summarize the system prompt", prompt-delimiter
  spoofing (`<|im_start|>`, `### Instruction`, `Human:`/`Assistant:` turns), and
  multilingual variants of the top 5 phrases.
- Build the benchmark the HANDOFF roadmap mentions: a fixture corpus (public
  injection datasets + your own benign chat logs) and a CI test that reports
  precision/recall and fails on regression. Until then the score is a vibe.
- Optionally add a pluggable "semantic" detector slot (a cheap classifier or a
  Haiku-class judge call) behind the same `Detector` interface, off by default.

## 4. The missing half: output & action tracking

To "track potentially problematic LLM output" the library needs an output pipeline
symmetric to the input one. Suggested `OutputScan` detectors, all pure and
zero-dep:

1. **Canary leak** (exists).
2. **Secrets / credentials in output** — API-key shapes (`sk-`, `AKIA`, `ghp_`,
   JWTs, PEM headers), plus any strings the app registers as sensitive
   (`shield.registerSecret(value)` → hashed, compared after normalization).
3. **PII** — email, phone, card numbers (Luhn-checked), SSN-like, addresses
   (opt-in per app).
4. **Exfiltration channels** — URLs/markdown images/links whose host is not on an
   app allow-list, especially with long query strings or base64-ish segments; HTML
   `<img src>`; `mailto:`.
5. **Untrusted-content echo** — output that reproduces text matched by an input
   injection excerpt, i.e. the model complied with the injected instruction.
6. **Tool-call policy** (the roadmap's "biggest gap") — inspect `tool_use` /
   `tool_calls` blocks before they execute: allow/deny by tool name, argument
   regex (URLs, paths, shell), and a "lethal trifecta" rule: if this turn's context
   contained untrusted content *and* a tool with side effects is being called,
   emit `tool_call_gated` and let the app decide (block / confirm / allow).
   Expose this as a `beforeToolCall(call, ctx) -> decision` hook in the wrappers.
7. **Refusal / policy signals** (optional) — detect the model saying it was asked
   to do something it refused; useful telemetry for "someone is probing".

Each detector emits a typed event with `direction: "output"` so the same log/CLI
covers both sides, and `shield status` gains output-side counts.

## 5. "General security issues"

Today this is one feature: a `ps`-scraping headless-browser tripwire, macOS/Linux
only, with `osascript` notifications. It is useful on your laptop, but it doesn't
belong in the same import as the LLM guard, and it isn't "general".

Recommendations:

- Move process-watch to the `/node` entry (or its own package) so browser and
  Python-web consumers never load it; document it as host-level tooling.
- For app-embeddable security signals, add cheap runtime checks that any app
  benefits from and that emit through the same bus: unsafe env (debug flags,
  default/placeholder API keys, world-readable secret files), outbound-request
  allow-list violations from the wrappers (custom `baseURL` pointing at an
  unexpected host — a classic "your SDK was reconfigured" signal), and SDK/dep
  version drift.
- For host-level "mysterious activity", keep it a separate daemon with its own
  install story; don't hardcode personal paths in a committed plist.

## 6. Suggested order of work

1. Fix the two P0 regexes + regression timing tests (both languages). Bump both
   versions together and add a CI check that they match.
2. Fix event durability: sync fs writes, pre-init buffer, wrappers auto-init the
   Node sink, `os.homedir()` + configurable path, per-line JSON parse.
3. Make the wrappers deny-by-default (Proxy in TS, explicit allow-list in Python),
   cover `responses`, `beta.messages`, `parse`/`stream`/`runTools`, `countTokens`.
   Duck-type the OpenAI wrapper.
4. Introduce `createShield(config)` with pluggable sinks and instance state; keep
   the current module-level API as a thin default instance so consumers don't
   break.
5. Add input normalization + the benchmark corpus; retune weights.
6. Build the output pipeline (§4), starting with secrets, exfil URLs, and the
   tool-call hook.
7. Split entry points (`/node`, `/react`, `/anthropic`, `/openai`), publish under
   real names, add `engines`, `browser`/`require` conditions, Node matrix, lint,
   mypy.
